# hashterm — outside review, 2026-09-17

Basis: read of README, `Cargo.toml`s, `page.rs`, `restore.rs`, CI, and a full build +
smoke test on Debian 13. **Not** based on daily use — nothing here judges the UX.

Measured: 10,070 lines across 7 crates · 51 `#[test]` fns in 16 files · 1 integration test
file · 12 `unsafe` blocks · 64 `.unwrap()` · 0 TODO/FIXME · 34 direct deps.

## Strong

- **Restore is threat-modelled.** `DENYLIST` covers `sudo`/`su`/`sudoedit`/`doas`/`passwd`/
  `ssh-add`, and the check walks the whole argv, so `env sudo …` is caught rather than just a
  leading token. Env capture is allow-listed to avoid recording secrets. Most terminals with a
  "restore my session" feature replay whatever they saw.
- **Untrusted output is treated as untrusted.** The title path strips control chars and caps at
  256, with the Pango main-thread DoS written down as the reason. That comment is why the
  behaviour survived a port to the older VTE API today.
- **`unsafe` is disciplined.** All 12 sites are trivial libc (`getuid`, `kill(pid,0)`,
  `localtime_r`, a pre-GTK `set_var`) or GObject qdata, each with a SAFETY note.
- **Supply chain is better than most funded projects.** `deny.toml` checking advisories, bans,
  sources and licenses, plus SLSA provenance attached to releases.
- **The core bet is right.** A private tmux server per tab delegates the hardest problem —
  survival across crashes — instead of reimplementing it. 10k lines for this feature set is lean.

## Worth fixing

1. **Panics at the external-input boundary.** 64 `.unwrap()`, concentrated exactly where tmux
   output and stored session state are parsed: `hashterm-tmux` 24 (`controller.rs` 12,
   `conf.rs` 7, `events.rs` 5) and `hashterm-session` 18 (`store.rs` 14). A malformed or
   unexpected tmux reply becomes a panic in the component whose promise is surviving crashes.
   This is the one item I'd fix before calling it production.
2. **CI runs no tests.** The only workflow is `slsa-release.yml`: it builds, audits and releases,
   but never runs `cargo test`, `clippy` or `fmt`. So the 51 tests are unenforced, and
   `[workspace.lints]` is empty. Odd gap for a project this careful about `cargo deny`.
3. **Coverage is thin where risk is highest.** `hashterm-session` is 2,360 lines of
   security-sensitive restore logic; it deserves the densest tests in the tree, including
   malformed-dump and hostile-argv cases.
4. **Only builds on rolling distros.** `vte4 v0_84` + `gtk4-layer-shell v1_3` exclude stock
   Debian 13 (VTE 0.80, layer-shell 1.0) — this year's stable. See the compat patch below.

## The Debian 13 compat patch (applied on adminvm, not upstreamed)

Lives in `~debian/src/h45h73rM1n41` on adminvm, `.orig` files kept beside each edit:

- `crates/hashterm-ui/Cargo.toml` — new feature `vte-termprops = ["vte4/v0_84"]`, default off.
- `crates/hashterm-ui/src/page.rs` — the `connect_termprop_changed` title handler is now behind
  `#[cfg(feature = "vte-termprops")]`; a `#[cfg(not(...))]` branch uses the classic
  `connect_window_title_changed` + `window_title()`, keeping the same strip-and-cap hardening.
- `packaging/build-deb.sh` — `Depends:` had a hardcoded `libvte-2.91-gtk4-0 (>= 0.84)`, set to
  `0.80` here. Better: derive it from `pkg-config --modversion vte-2.91-gtk4` at package time so
  the declared dep always matches what was actually linked.

Semantics differ slightly: `window_title_changed` fires on OSC 0/2 with the title directly, vs a
typed termprop. Equivalent for strip-and-cap use; you know the edge cases better.

Build on Debian 13 after the patch: `cargo build --release` clean, `.deb` installs, app starts
(`x11-ewmh` overlay, Portal hotkeys), maps its drop-down, spawns its private tmux server.
